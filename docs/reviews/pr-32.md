## Findings

### P2-1: A changed calibration load bypasses the calibration table

Status: fixed in `7eaf4f621f22eb0960115066ae569959ae3dc917`.

Open at: `deb04a7929c6f0fc2eea62295d64e66c6364e66b`.

File: `web/src/lib/workout.ts:475-481`.

Trigger: The owner changes the calibration weight with the stepper, then logs a result such as 6 reps in reserve.

Expected: The table applies to the load that the owner logged (D-150, D-267). The weight stepper allows a change before the log (D-249).

Actual: `calibrationLoad` returns null unless the logged weight equals the plan's `keep` load. `nextSet` then uses the unchanged working target.

Consequence: A valid calibration result does not set the working load that the table specifies. The phone can show the original load after a different calibration load and result.

Correction: Apply the table to the logged calibration load, or prevent a weight change when the stored plan cannot support it.

Regression check: `make web` passed. Its unit test checks changed calibration loads at 100 and 300, and its browser test checks a changed load offline.

### P2-2: Finishing clears a skip after the exercise has a logged set

Status: withdrawn.

Open at: `deb04a7929c6f0fc2eea62295d64e66c6364e66b`.

File: `web/src/lib/workout.ts:433-445`.

Trigger: The owner logs one set, skips that exercise, then finishes the workout.

Expected: Keep the skip in the finished header and its outbox payload (D-63, D-132). The policy must distinguish the skipped exercise from ordinary incomplete work (D-170).

Actual: `finishWorkout` replaces `skippedExerciseIds` with exercises that have no logged set. It removes the skipped id when any set exists.

Consequence: The server never receives the owner's skip for a partially logged exercise. Its workout converter also omits a skip id when the exercise has any set.

Evidence: The response cites the API rule in `proto/workoutapp/v1/workout_service.proto`, the rejection in `go/internal/domain/log.go`, and the matching policy check. D-170 treats each planned set without a log as skipped work. The server cannot represent a skipped exercise with logged sets, and its policy uses the same target for that partial log.

Regression check: None. The cited API and domain checks refute the requested state.
