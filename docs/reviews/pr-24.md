## Findings

### P1-1: A seated calf raise passes a knee injury filter

Status: open.

Open at: `fe99aed9b4b531e3dc8fe16aa0f4465b8bd1c23d`.

File: `go/internal/domain/body_data.go:36`.

Trigger: The owner selects a knee injury and has a seated calf-raise machine. The catalog has one `calf_raise` id for both seated and standing forms.

Expected: D-208 requires the server to remove an exercise that loads an injured area. Section 5.15 of `docs/research/exercise-safety.md` states that the seated form puts a pad load on the knee.

Actual: The table maps `calf_raise` to the lower back and ankle only. `profile.ForPlan` therefore includes it for a knee injury.

Consequence: The planner can receive an exercise that loads the selected injured area. The table also records this known gap at `docs/research/exercise-safety.md:627`.

Correction: Split the forms into distinct exercise ids, or use a conservative area set that includes the knee for this shared id. Add a regression check for a knee injury.

Regression check: `make go-test` and `make emulator-test` passed, but neither check asserts the seated calf-raise case. Add and pass a focused planner-input check that excludes `calf_raise` for a knee injury.

### P2-1: Invalid list values can echo profile text

Status: open.

Open at: `fe99aed9b4b531e3dc8fe16aa0f4465b8bd1c23d`.

File: `go/internal/profile/profile.go:106,156`.

Trigger: A caller sends profile text such as an injury note in an enum or list field, such as `experience` or `muscle_groups`.

Expected: D-80 permits ids alone in error reports. The API comment in `proto/workoutapp/v1/profile_service.proto` also says an error never includes profile text.

Actual: `Profile.Check` formats the unknown value into the error. The service returns that error as `INVALID_ARGUMENT`.

Consequence: Arbitrary profile or health text can cross the API boundary in an error response and can enter error reporting by a caller.

Correction: Return a field-only error for unknown enum and list values. Do not include untrusted input in the error text.

Regression check: Add a service test that sends synthetic health text in enum and list fields. Confirm that each returned error omits it.
