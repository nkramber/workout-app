## Findings

### P2-1: Exported kind and region lists can change validation

Status: open.

Open at: `6da346c91f3179ac472a91434905aa993770987e`.

File: `go/internal/domain/catalog.go:16,33,72-73`.

Trigger: A caller appends an unsupported value to the exported `Kinds` or `Regions` slice, then checks a catalog that uses that value.

Expected: `Catalog.Check` accepts only the four defined kinds and six defined regions (D-155, D-161).

Actual: `known` reads the exported mutable slices. A caller can add an unsupported kind or region, after which `Catalog.Check` accepts it.

Consequence: A catalog can pass validation with a kind or region outside the product contract.

Correction: Keep the validation sets private or use a fixed switch. Expose copies if callers need ordered lists.

Regression check: Add a test that mutates an exposed list and confirms that validation still rejects an unsupported value. The current `make go-test` passes, but it has no such test.

### P2-2: A valid extreme dumbbell range can make weight expansion loop forever

Status: open.

Open at: `6da346c91f3179ac472a91434905aa993770987e`.

File: `go/internal/domain/inventory.go:30-40`.

Trigger: Call `Weights` with `Lightest: 1`, `Heaviest: Load(math.MaxInt64)`, and `Step: 1`. `Check` accepts this set.

Expected: A valid set returns its available weights, or the check refuses a range that the method cannot expand (D-54, D-155, D-160).

Actual: After the loop reaches `math.MaxInt64`, `w += d.Step` overflows to a negative value. The `w <= d.Heaviest` condition remains true, so the loop does not end.

Consequence: `InventoryEntry.Available` can stop its caller indefinitely for a structurally valid inventory entry.

Correction: Stop before an addition can overflow, or reject ranges that the method cannot safely expand.

Regression check: Add a boundary test for the maximum `Load` value and confirm that expansion returns or validation rejects the range. The current `make go-test` passes, but it has no such test.
