## Findings

### P2-1: A failed plan store operation loses the revision

Status: open.

Open at: `a5451328baf687ec3ea13b8c5356cad7b96c6e24`.

File: `go/internal/workoutsvc/workoutsvc.go:117-118`.

Trigger: `SyncOutbox` applies a finished workout, then `Reviser.Revise` gets a transient error while it reads or writes the plan.

Expected: The sync must retry the revision after a transient store failure. D-292 requires a revision after the sync applies a finished workout.

Actual: `s.revise` logs the error and returns no status. `SyncOutbox` then returns an applied result. The phone deletes the outbox entries, so it does not retry the revision.

Consequence: Firestore keeps the workout log, but the plan keeps its old targets and the owner gets no retry path.

Correction: Return a retryable error when a revision store operation fails. The phone can replay the entries, and the reviser can retry after the idempotent workout apply.

Regression check: Update `TestSyncOutboxRevises`. Assert a retryable error, replay the entries, and assert one revision. Not run.
