## Findings

### P2-1: The deload lasts eight calendar dates

Status: open.

Open at: `35cf4efd195fa2c5290c1886acff4fda1eef93a4`.

File: `go/internal/policy/disrupt.go:74-80`.

Trigger: Start a deload on a date, then request a target seven dates later.

Expected: D-295 specifies a seven-day deload. The final deload date must be six days after its start.

Actual: `deloadOf` includes `from + DeloadDays`. With `DeloadDays == 7`, it includes both the start date and the next seven dates. `TestDisruptions` labels the eighth calendar date `h_deload_last_day` and expects a deload.

Consequence: The policy gives reduced targets for one extra day and delays the return to pre-deload targets.

Correction: End the deload before `from + DeloadDays`. Change the boundary test to assert that the target returns on that date.

Regression check: `go test ./internal/policy` must cover the start date, the last date within seven days, and the first date after seven days. Not run after a correction.

### P2-2: A dated plan read keeps a stale override

Status: open.

Open at: `35cf4efd195fa2c5290c1886acff4fda1eef93a4`.

File: `go/internal/revise/dated.go:72-80`.

Trigger: Save an override, then request the plan after a 7-day missed-session gap or a 14-day long break, before the next workout.

Expected: D-294 and D-179 apply the date-based target rules to the target for the next session. D-293 says the rules read the override as that target. The checked result must reach the workout.

Actual: `ForDate` evaluates the stored recommendation as `e.Target`, then copies `e.Override` unchanged into the result. `workoutExercises` selects the override's stored sets whenever the override exists. The workout therefore uses the old override, including its old reps-in-reserve, after the date-based rules change the recommendation.

Consequence: The workout can show and use a target that does not include the required missed-session hold or long-break reduction.

Correction: Apply the date-based rules to the effective target, including the override, and preserve the separate recommendation and reason records. Add a regression case for a dated read with an override after each affected gap.

Regression check: `go test ./internal/revise ./internal/plansvc` and the web workout test must prove that the policy-adjusted override reaches the workout. Not run after a correction.
