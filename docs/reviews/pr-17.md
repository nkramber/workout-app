### P2-1: Cache-write tokens are undercounted

Status: fixed in `0bd93c395033e12f22029d670af19cb5a73ce355`.

Open at: `21ed99848b97396da886cd4aa0417ed5a34a2226`.

File: `go/internal/ai/cost.go:48-58`.

Trigger: The API writes an eligible prompt prefix to its cache. The prompt exceeds the cache minimum, and the reply reports cache-write tokens.

Expected: The cost record must charge each token at its published rate. The cap must reserve enough for the worst-case charge (D-25).

Actual: At `21ed998`, `Cost` charged cache-write tokens at the ordinary input rate, and the OpenAI provider did not read `cache_write_tokens`. The correction adds that usage field and price. It subtracts cache reads and writes from ordinary input tokens, then charges each category at its rate. The cap reserves each request byte at the highest input rate. The client refuses requests over 272,000 bytes, so each accepted request remains in the short context.

Consequence: At the earlier head, the cost record understated cache-write cost, and the cap permitted a call above its reservation. The correction closes both paths.

Correction: Read `cache_write_tokens`, include its rate in `Prices` and `Cost`, reserve the highest input rate, and refuse requests over the short-context limit.

Regression check: `TestOpenAICacheWriteCost` checks the published rates. `TestWorstCoversEachRate` checks the reservation against each input-rate mix. `TestCapBoundary` checks the cap boundary, and `TestRequestLimit` checks that an oversized request makes no provider call. All tests pass in `make go-test`.
