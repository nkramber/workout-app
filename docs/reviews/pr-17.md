## Findings

### P2-1: Cache-write tokens are undercounted

Status: open.

Open at: `21ed99848b97396da886cd4aa0417ed5a34a2226`.

File: `go/internal/ai/cost.go:48-58`.

Trigger: The OpenAI API writes an eligible prompt prefix to its cache. The prompt exceeds the cache minimum, and the response reports cache-write tokens.

Expected: The cost record must use the price for each billed token, and the cap must reserve enough for the worst-case cost (D-25).

Actual: `Cost` charges each input token that is not a cache read at the ordinary input rate. `openaiResponse` drops `cache_write_tokens`. The cap reserve uses the ordinary rate for each input byte.

OpenAI's [prompt-caching guide](https://developers.openai.com/api/docs/guides/prompt-caching), read 2026-10-01, says caching is on by default. It says GPT-5.6 and later cache writes cost 1.25 times the ordinary input rate. It also says usage reports `cache_write_tokens`. The [pricing page](https://developers.openai.com/api/docs/pricing), read 2026-10-01, lists the cache-write rate for GPT-6 Luna.

Consequence: The record understates the cost of a cache write. The cap can also permit a call whose billed cost exceeds the reserved amount and the configured cap.

Correction: Read `cache_write_tokens`, include its rate in `Prices` and `Cost`, and reserve the maximum input charge that applies to this request. Add a local-server test for cache-write usage and a cap-boundary test.

Regression check: Add a response with cache-write usage. Check its cost against the published rates, and check that the cap refuses a call above its limit. No such regression test exists.
