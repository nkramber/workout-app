## Findings

### P2-1: A missing plan link panics during request parsing

Status: withdrawn.

Open at: `f75610ada389847bbde34b97fc435b22fbfda772`.

File: `go/internal/workoutsvc/workoutsvc.go:157-160` at `f75610a`.

Trigger: Send a `workout` payload whose `plan` field is absent.

Expected: Refuse the malformed header as `INVALID_ARGUMENT`. The contract requires a plan link (D-248).

Actual: The generated `GetPlan` and `GetSessionIndex` getters accept a nil receiver. The missing plan produces a zero time, and `Entry.Check` refuses it as a bad plan link.

Consequence: The request gets the defined refusal. This trigger causes no defect.

Correction: The code needs no change.

Regression check: `go test ./internal/workoutsvc/ -run TestSyncOutboxRefuses -v -count=1` at `a20f04b` passed. The test checks the plan-link refusal and confirms that the store holds no workout.

### P2-2: Entity versions collide when distinct entity IDs match

Status: open.

Open at: `a20f04be10e336d7a551530a23e85a48ac9c9399`.

File: `go/internal/workout/workout.go:311-315`.

Trigger: Apply a workout header with UUID `A`, then apply a set entry with UUID `A` in that workout. The contract gives each entity a UUID and does not require unique UUIDs across entity types.

Expected: The header and the set are distinct entities, so the first apply of each returns version 1.

Actual: `Apply` stores versions under `e.EntityID` alone. The focused reproduction returned header version 1 and set version 2.

Consequence: `SyncOutbox` returns a wrong server version for the set. The phone can then store an incorrect `base_version` for that entity.

Correction: Key the version by entity type and entity id, or use separate version state for each entity type. Add a regression test for UUID collisions across entity types.

Regression check: A temporary focused program using `workout.Apply` reproduced the result `header version=1 set version=2`. Add a unit test that expects version 1 for each entity after the correction.
