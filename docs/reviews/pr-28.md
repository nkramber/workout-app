## Findings

### P2-1: The fake delay accepts values above its limit after overflow

Status: open.

Open at: `26f1283e484fa4691f35d4831942435efac6007b`.

File: `go/cmd/api/main.go:92-97`.

Trigger: Set `LUNA_FAKE_PROVIDER=1` and set `LUNA_FAKE_DELAY_MS=9223372036855` on a 64-bit build. `strconv.Atoi` accepts this value, but the conversion and multiplication overflow to a negative duration.

Expected: D-241 says the local switch accepts a delay from 0 to 60000 milliseconds and refuses other values.

Actual: The overflowed negative duration is not greater than `maxFakeDelay`, so the API accepts the out-of-range value and installs a fake with no delay.

Consequence: An invalid local test configuration passes the start guard and removes the delay that makes progress visible. The bounds check does not enforce the documented range for all accepted integer inputs.

Correction: Compare the parsed integer with `maxFakeDelay.Milliseconds()` and `time.Duration` conversion.

Regression check: Add a test with a large valid `int` above the limit that causes duration multiplication to overflow. The function must return an error that names `LUNA_FAKE_DELAY_MS`.

### P2-2: The no-exercise error omits the unchanged-plan text

Status: open.

Open at: `26f1283e484fa4691f35d4831942435efac6007b`.

File: `web/src/lib/plan.ts:50-51`.

Trigger: Request a plan when the owner has no confirmed machine that supplies an allowed exercise. The server returns `FAILED_PRECONDITION`, which selects `NO_EXERCISE`.

Expected: D-240 says each plan request error states, “Your plan did not change.” The same requirement appears in `docs/design.md` section 3.3.

Actual: `NO_EXERCISE` says to confirm a machine or change injuries, but does not say that the stored plan did not change. If an earlier plan exists, the screen retains it and shows this error.

Consequence: The owner does not get the required confirmation that the previous plan remains in effect after a failed request.

Correction: Add the unchanged-plan statement to this error text and update its exact unit and browser assertions.

Regression check: Assert the full no-exercise message includes “Your plan did not change.” in the unit test and the no-machine browser test.
